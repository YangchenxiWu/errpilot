# Raw socket volatility impact assessment, V1

This is an assessment of the unchanged `V6_LIVE_DAEMON_TOPOLOGY_OBSERVATION_CONTRACT_V1`. It constructs and adopts no replacement contract. The accepted topology SHA is `3a9166d306fee282279702312d6e170cad6f3a1f60b8ce70bb6e3e579af746ea`; the correction snapshot SHA is `f7dcd64c808aae7b8e9db4e0835594b1f7a488ec52b186686a9f362a84aa65ac`. Historical observations are not current live facts.

The accepted raw table has four records; the correction table has six. Every original record remains byte-exact. The named buildkitd listener has inode 340, Flags `00010000`, Type `0001`, State `01`; the otel-grpc listener has inode 344 with those same listener fields. The added records have addresses `00000000319c26ff` and `000000002eda958e`, inodes 18643 and 14575, zero listen flags, stream Type `0001` and State `03`. The former bears `/run/buildkit/buildkitd.sock`; the latter is unnamed. These are added connected records, not evidence of listener replacement or inode renumbering. See `socket_diff_analysis.json` and the exact raw text copies.

Connected sockets represent runtime connections rather than a durable configuration declaration. An unnamed entry is not an assertion that a new public listener exists. Nevertheless, an unexpected connected client can have operational-security significance. Neither the initiating client, authorization of that client, exact lifetime, nor a mapping from either inode to Exec A/B is established here. Both additions are therefore classified **UNRESOLVED**, rather than claiming measured transience or harmlessness. No current table was obtained: **CURRENT_SOCKET_TABLE_NOT_REOBSERVED**.

As a technical inference, creating or closing legitimate Unix connections can add or remove connected entries. New sockets can receive different inodes and kernel diagnostic addresses; inode reuse can also make an apparent match insufficient to establish continuous socket identity. Exact full-table equality consequently binds the current population of runtime connections, ordering and diagnostic identifiers in addition to the listener configuration. Equality is a conservative frozen V1 gate, but this evidence does not establish that it is a reliable availability condition for semantic preclaim freshness under ordinary concurrent clients.

The preserved observer source explicitly invokes `buildctl --addr=unix:///run/buildkit/buildkitd.sock debug workers` before reading the socket table. That worker observation is itself a potential BuildKit client connection. A dial-stdio process is another candidate connection source. The recorded observations do not prove that either command created either added inode, or that a connection remained open when the later table was read. Executing `cat /proc/net/unix` is distinct from opening a connection to buildkitd. Likewise, this transaction's host Docker Engine GET connection is in a different connection context and must not be equated with a buildkitd connection inside the daemon container.

Two consecutive legitimate observer reads could therefore differ in full raw bytes when client activity overlaps them. This is a possibility implied by connection lifetime, not a fresh experimental result: no consecutive current `/proc/net/unix` reads were performed. The historical correction snapshots retain the same socket additions; no claim of measured removal or lifetime is made. The present GET/top observations independently show ExecID/process turnover, which supports the need to retain concurrency diagnostics but does not establish any particular socket-to-exec connection.

Any future policy would still need to enforce the exact approved Unix endpoint and path, listener Type/Flags/State, intended daemon ownership, restrictive permissions/access, absence of unapproved TCP or Unix listeners, exact executable/image/config pins, accepted worker/platform, internal-only network and no external/default daemon route, exact two-network proxy topology, no published ports, exact proxy source/policy/enforcement identity, and independent receipt freshness before claim/build. Raw tables, all connected records and ExecIDs would remain retained and reviewed; unexplained clients would require explicit handling. An endpoint listener check alone would not establish egress enforcement or authorized-client integrity.

There is no semantic fallback in this package. The frozen V1 exact-byte requirement remains authoritative, historical topology mismatch remains a blocker, current complete topology identity remains unobserved, and all operational cleanup, source acceptance and installation gates remain closed.
