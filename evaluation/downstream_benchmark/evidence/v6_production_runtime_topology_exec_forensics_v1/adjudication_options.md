## Option B — Design a future versioned semantic-stability topology contract

**PREREQUISITES:** Explicit Human-PI authorization to design a versioned successor contract and evaluate its impact. Preserve complete original/correction/current raw evidence and all observed differences. Define an exact security projection plus instance/freshness bindings and separate socket/ExecID diagnostic records. Specify behavior for missing observations and unexpected clients; unknown required security evidence must fail closed. Independent Human-PI review and acceptance are required before effectivity, with no fallback to an older pin or authority.

**BENEFITS:** Can distinguish configured security boundaries and required instance identity from runtime connection bookkeeping, while retaining the raw observations for attribution and audit. May avoid rejecting legitimate concurrent diagnostic activity solely because it changes an unnamed socket inode.

**RISKS:** A badly specified projection can conceal unauthorized clients, extra endpoints, daemon replacement, stale worker identity, image/config confusion, default routes or broader proxy policy. Removing a check because its present observation is inconvenient would be unsound. The successor must explicitly preserve exact image/config and binary pins, dedicated daemon identity, worker/platform, exact Unix endpoint and listener ownership/permissions/type/state/flags, absence of extra TCP/Unix listeners, internal network identity and `Internal=true`, exact allowed participants, daemon internal-only attachment/no external or default route, proxy exactly dual-homed, DNS restrictions, no published ports, exact proxy source/policy/enforcement identity, and receipt freshness before claim/build. Volatile connected entries and ExecIDs remain recorded and unexpected-client handling must be reviewed. Changes to freshness semantics require new provider/receipt/hash-graph qualification.

**SCIENTIFIC_EFFECT:** An implementation-governance change, not new scientific validation. Any comparability or evidence-validity consequences require explicit assessment before adoption. No real work or scientific claim changes occur here.

**AUTHORITY_REQUIREMENT:** Separate Human-PI design authorization, independent contract/source/qualification acceptance, and distinct canonical/runtime installation authority. No successor contract is constructed or adopted in this package.

**NEXT_LEGAL_GATE:** Human-PI adjudication, followed only if selected by an explicitly bounded versioned semantic-stability contract design transaction. Installation/publication/real execution remain later gates.
