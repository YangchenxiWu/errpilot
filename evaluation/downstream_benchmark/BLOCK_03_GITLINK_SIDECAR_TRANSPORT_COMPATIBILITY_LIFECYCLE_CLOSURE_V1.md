## Frozen source-package transport semantics

A governed gitlink-bearing source snapshot is one atomic logical package:
**source filesystem tree + identity-bearing sibling gitlink provenance sidecar**.
The unchanged exporter owns `sidecar_path(source)`, mechanically deriving
`source.with_name(source.name + ".gitlinks.json")`. For `context / "source"`,
the same function derives `context / "source.gitlinks.json"`.

`transport_source_package()` verifies the source manifest and governed hash,
reads the original sidecar through the accepted no-follow regular-file reader,
copies the source tree with preserved symlinks, and writes exactly the original
sidecar bytes to the helper-derived sibling destination. It never derives,
regenerates, normalizes, reconstructs, or acquires gitlink provenance.

Destination provenance is re-read and verified against the accepted manifest,
governed source identity, and exact original companion bytes before any real
engine runtime/Docker operation. All destination contexts are staged and
verified before the first base probe or build. Integration ordering is verified
statically; the real engine is not invoked by this transaction.

Missing or mismatched required source/destination sidecars, malformed or
substituted companion data, wrong provenance, altered source identity, or altered
placeholder/tree fail closed with `BLOCKED_INPUT_IDENTITY`. Silent sidecar loss
is disallowed. Such rejection is input-identity evidence, not an exclusion,
build failure, eligibility decision, or environment-readiness increment.

Non-gitlink historical transport gains no sidecar and preserves filesystem
bytes, modes, raw symlink targets, source identities, and context identities.
Provenance serialization and source snapshot hashing remain unchanged.
